UAV TASK · RECONNAISSANCE ALLOCATION

无人机侦察任务聚合
与异构资源分配

面向 C172 与 SF50 两类平台、约 10 架飞机，将前端任务规划结果转换为可验证的飞机—载荷—任务分配方案。

输入

规划任务 + 聚合任务组

保留任务依赖、区域、时间窗口、能力和载荷需求。

求解

候选筛选 + CP-SAT

先剔除能力不满足的平台，再进行全局分配。

输出

主任务 + 备用 + 航迹接口

为后续航迹规划提供任务顺序、区域和载荷标识。

基于 YaqiChang/UAV-task 当前实现 · 离线仿真验证

01 · REQUIREMENT ANALYSIS

需求拆解：从前端任务到可执行资源方案

R1
接口承接读取 planner output、aggregation output、fleet snapshot 和已完成任务状态，避免任务聚合后丢失前置依赖。
R2
异构平台与载荷区分 C172、SF50 的飞行能力，并将 VISIBLE、INFRARED、RADAR 映射到可用虚拟载荷。
R3
约束可行性同时检查载荷、飞行能力、时间窗口、高度范围、任务时长、平台可用状态和依赖关系。
R4
资源分配每个任务组分配给满足约束的飞机，允许同一飞机承接多个时间不冲突的任务组，并保留备用飞机。
R5
下游消费输出飞机任务包、任务顺序、目标区域、载荷和时间范围，供航迹规划模块继续处理。
研究边界
当前验证任务聚合与资源分配中间层，航迹点、通信带宽、燃油精算和飞控执行保留给下游模块。

03 · CORE ALGORITHM

核心算法：候选集约束下的任务组分配

STEP 01

任务标准化

统一任务和任务组字段，将成员任务的载荷、能力和约束汇总到任务组层级。

G = Normalize(T, Groups)
payload(G) = ∪ payload(Tᵢ)schemas.pynormalize.py
STEP 02

候选平台构造

只有同时满足载荷、飞行能力、平台状态和工作时长的平台进入候选集合。

C(g) = { a | payload(g) ⊆ payload(a)
∧ capability(g) ⊆ capability(a) }candidate_filter.py
STEP 03

CP-SAT 分配

在候选集合上联合决定任务组归属，生成主任务飞机和备用飞机。

x[g,a] ∈ {0,1}
Σₐ x[g,a] = 1
a ∈ C(g)cp_sat_allocator.py

硬约束

任务组只能分配给候选平台。
任务组分配满足依赖、任务时长和时间不冲突条件。
平台可用状态和剩余工作时长必须满足任务需求。

优化目标与回退

优先级、平台类型和任务负载进入分配代价。
安装 OR-Tools 时使用 CP-SAT，结果记录求解状态和目标值。
缺少 OR-Tools 时使用确定性回退，便于接口测试。

04 · VALIDATION & SCOPE

验证结论与当前边界

已经验证的内容

  • 接口：三类前端快照可以进入统一分配入口。
  • 聚合：任务组成员、目标区域和任务顺序被保留。
  • 匹配：VISIBLE、INFRARED、RADAR 能映射到对应虚拟载荷。
  • 筛选：缺少 LOITER、RADAR 等原因会被记录。
  • 优化：CP-SAT 返回可行分配和求解状态。
  • 异常：依赖缺失与载荷缺失分别输出 BLOCKED、INFEASIBLE。

汇报时需要限定的结论

  • 平台：C172、SF50 参数来自手册整理后的仿真 profile。
  • 载荷：MX-15、Lynx 的兼容关系用于算法验证。
  • 代价：当前任务组使用估计工作量，精确航程和燃油由航迹层补充。
  • 通信：静态链路字段保留扩展位置，尚未进行带宽竞争求解。
  • 执行：尚未向 X-Plane、飞控或在线重规划服务发送指令。
  • 实验：当前结果证明分配逻辑和接口链路可运行，不代表真实飞行性能。
当前阶段的技术结论
前端任务规划和任务聚合结果已经可以通过标准化、依赖校验、候选筛选和 CP-SAT 分配转换为结构化飞机任务包，并对可分配、依赖阻塞和资源不可行三类状态给出可追溯结果。
